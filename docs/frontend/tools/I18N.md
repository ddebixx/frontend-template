# Internationalization (i18n)

User-facing copy must be localizable from day one. Inline static strings in components and pages make UI hard to scan and harder to translate.

Both templates ship with i18n wired (`en` + `pl` sample catalogs and a locale switcher).

## Copy placement (no inline static strings)

**Do not** embed display text as string literals inside component / page / feature files.

Keep those files structural: markup, composition, and wiring. Visible (and a11y) copy lives elsewhere.

Choose **one or both** of these homes — the project decides:

| Home | Use when |
| --- | --- |
| **Locale catalogs** (`src/messages/*.json`) | Copy must be translated / switched by locale |
| **Constants** (`*.constants.ts` or `src/constants/`) | Single-locale or non-translated labels; keep UI files clear |

```tsx
// ❌ Static string in the component / page
export const SaveButton = () => <button type="button">Save changes</button>;

// ✅ Locale catalog
export const SaveButton = () => {
  const t = useTranslations("Common");
  return <button type="button">{t("saveChanges")}</button>;
};

// ✅ Constants sibling (also fine — team choice)
import { SAVE_CHANGES_LABEL } from "./SaveButton.constants";

export const SaveButton = () => (
  <button type="button">{SAVE_CHANGES_LABEL}</button>
);
```

**Guidance, not dogma:** prefer catalogs when the app is multi-locale; prefer (or also use) constants when you only need a clean component file. Mixing is OK (e.g. i18n for product UI, constants for demo/sample modules). Document the team default in the project README if it differs from “i18n for user-facing copy”.

**Exceptions** (not “display copy”): class names, URLs, analytics event names, enum/discriminators, test-only fixtures.

## Defaults by variant

| Variant | Stack in template |
| --- | --- |
| Next.js App Router | [`next-intl`](https://next-intl.dev/) — request config + cookie locale (`locale`) |
| Vite + React | [`i18next`](https://www.i18next.com/) + [`react-i18next`](https://react.i18next.com/) |

Forks may pick another library — document the choice in the project README and keep the **conventions below**.

## Layout

```txt
src/
  i18n/
    config.ts              # locales, defaultLocale, isLocale
    messages.ts            # static catalog map (keeps both locales referenced)
    request.ts             # Next only — next-intl getRequestConfig
    setup.ts               # Vite only — i18n.init + document lang sync
  messages/
    en.json
    pl.json
  components/shared/LocaleSwitcher/
```

- Keep catalogs **flat-ish namespaced keys** (`HomePage.title`, `Common.locale`)
- One file per locale (split by domain only when a catalog becomes huge)
- Do not invent a second parallel copy store under `features/`

## Usage

### Next.js (RSC)

```tsx
import { getTranslations } from "next-intl/server";

export default async function Page() {
  const t = await getTranslations("HomePage");
  return <h1>{t("title")}</h1>;
}
```

Client components: `useTranslations` from `next-intl`. Locale is stored in the `locale` cookie (see `LocaleSwitcher`).

### Vite

```tsx
import { useTranslation } from "react-i18next";

export const Page = () => {
  const { t } = useTranslation();
  return <h1>{t("HomePage.title")}</h1>;
};
```

Import `src/i18n/setup` once from the app entry (`main.tsx`).

## Rules

1. **No inline display strings** in components / pages / features — use locale keys **or** constants (see above)
2. **Keys show intent** — searchable, stable; never recycle a key for different meaning
3. **Interpolation only via the i18n API** — don’t concatenate translated fragments in ways that break grammar
4. **Format dates, numbers, lists, plurals** with the library / `Intl` — not handmade string math
5. **Locale drives `lang`** — Next sets `<html lang>` from `getLocale()`; Vite syncs `document.documentElement.lang`
6. **a11y strings follow the same rule** — `aria-label`, `alt`, toasts, validation messages live in catalogs or constants
7. **Server vs client** — Next: prefer `getTranslations` in RSC; use client APIs only where needed

## Anti-patterns

```tsx
// ❌ Hardcoded copy in the UI file
<button>Save changes</button>

// ✅ Message key
<button>{t("common.saveChanges")}</button>

// ✅ Constant
<button>{SAVE_CHANGES_LABEL}</button>
```

```ts
// ❌ Broken grammar / locale
`${t("items")}: ${count}`

// ✅ Plural / interpolation via i18n
t("cart.itemCount", { count })
```
